# 水平扩展 / 多实例部署说明

本项目的实时通信基于 Socket.IO。单实例时可开箱即用；要跑多进程或多台机器，需要：

1. **Redis Adapter**：让不同实例之间能互发 Socket.IO 事件。
2. **Sticky Session**：让同一个客户端的 HTTP / WebSocket 请求固定落到同一个实例。
3. **定时任务只跑一个实例**：`BB_ENABLE_TIMERS=false` 关闭其余实例的 House 定时器。
4. 所有实例共享同一个 **MongoDB** 和同一个 **JWT_SECRET**。

---

## 1. 启用 Redis Adapter

在 `backend/.env` 中配置：

```env
REDIS_URL=redis://127.0.0.1:6379
```

重启后启动日志会出现 `[Socket.IO] Redis Adapter 已启用`。未配置 `REDIS_URL` 时自动退化为单实例内存 Adapter。

依赖已在 `package.json` 中声明：

- `@socket.io/redis-adapter`
- `redis`

---

## 2. Nginx Sticky Session

Socket.IO 默认会先用 HTTP polling 握手（除非强制 `transports: ['websocket']`）。多实例下轮询请求必须落到同一实例，否则会报 `Session ID unknown`。

### 方式 A：使用 nginx sticky 模块（推荐）

```nginx
upstream bb_backend {
    sticky cookie srv_id expires=1h path=/;
    server 127.0.0.1:3000;
    server 127.0.0.1:3001;
}

server {
    listen 443 ssl;
    server_name wil-bigbrother-game.site;

    location /api/ {
        proxy_pass http://bb_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /socket.io/ {
        proxy_pass http://bb_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }

    location / {
        root /var/www/luck-stage-simulator;
        try_files $uri $uri/ /index.html;
    }
}
```

`sticky` 需要 `nginx-plus` 或开源版编译 `nginx-sticky-module-ng`。

### 方式 B：`ip_hash`（简单，但同一出口 IP 的客户端会集中到同一实例）

```nginx
upstream bb_backend {
    ip_hash;
    server 127.0.0.1:3000;
    server 127.0.0.1:3001;
}
```

> 若前端强制只使用 WebSocket（`transports: ['websocket']`），可降低对 sticky 的依赖，但仍建议配置。

---

## 3. 定时任务只跑一个实例

House 的移动完成、自动睡眠、洗澡结束由 `setInterval` 驱动。多实例同时运行会重复处理。

在除主实例外的 `.env` 中设置：

```env
BB_ENABLE_TIMERS=false
```

主实例保持默认（或不设置）。

---

## 4. 启动多实例示例（PM2）

```bash
# 主实例：处理定时任务
BB_ENABLE_TIMERS=true PORT=3000 pm2 start src/index.js --name bb-0

# 从实例：不处理定时任务
BB_ENABLE_TIMERS=false PORT=3001 pm2 start src/index.js --name bb-1
```

两个实例需读取相同的 `.env`（MongoDB / JWT_SECRET / REDIS_URL / BB_ADMIN_PASSWORD）。

---

## 5. 已知限制

以下状态目前保存在**单个进程内存**中，跨实例时需要改造为 Redis/数据库存储：

- HOH 邀请 `pendingInvites`
- 同行邀请 `pendingMoveInvites`
- 部分「强制移动」只对本地 socket 生效的旧逻辑（已尽量改为通过 `user:<id>` 房间广播）

在启用多实例前，建议：

- 先只开一个实例验证 Redis 连通；
- 观察 `house:invite-received`、`house:move-invite-received` 是否跨实例正常；
- 如需完整支持，下一步可把邀请状态迁移到 Redis 并设置 TTL（与现有的 2 分钟过期一致）。
