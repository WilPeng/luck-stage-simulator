# 前端性能优化排查策略（乘风速运赛）

> 目标：消除重复请求、请求风暴、无谓轮询、渲染卡顿、Socket 抖动，让选手/管理员端流畅。

---

## 一、排查策略（分层）

### 1. 网络层（Priority: 高）
- **重复请求**：同一接口在短时间内被多次调用（onMounted 多次、watch 触发、useSfRefresh 无过滤）。
- **请求风暴**：某操作一次触发 N 个请求（如 foreach 轮次全量拉取）。
- **无分页大表**：`pageSize=1000/999/10000` 一次性拉全量再前端分页。
- **轮询频率**：setInterval 间隔过小（1~3s）。
- **WebSocket**：每条写操作都广播 → 触发大量页面刷新；隧道环境 socket 反复重连。

**排查命令**：全局搜索 `setInterval`、`pageSize: 1000+`、`socket.io-client`、`fetchUsers(`、`for (let r`。

### 2. 渲染层（Priority: 中）
- 大列表无虚拟滚动（`v-for` 渲染上千节点）。
- 同一数据多组件重复计算（computed 滥用、watch 深层）。
- 频繁重挂载（router-view `:key` 随每次写操作变化）。

### 3. 生命周期层（Priority: 高）
- 定时器未清理（onBeforeUnmount 漏 clearInterval）。
- 事件监听/ socket 未注销 → 内存与请求泄漏。
- 页面隐藏（切后台）仍在轮询。

### 4. 构建层（Priority: 中）
- 未做路由懒加载 / 代码分割。
- 大依赖未按需引入。

## 二、本次扫描结果

### 网络层
| 问题 | 位置 | 处理 |
|---|---|---|
| 请求风暴：赛季变化时 `for r=1..10 loadGroupingMode` | AdminLayout / PlayerLayout | ✅ 改为只拉当前轮 |
| WebSocket 每写必广播 → 全页面刷新 | 全局 | ✅ 前端 socket 停用（`sfRealtimeStore` no-op），dist 已无 `game-realtime` |
| `useSfRefresh` 无过滤/无去抖 | composables | ✅ 支持路径匹配 + 350ms 去抖 |
| 大表无分页 | 歌曲库 `/songs`、操作日志 `/logs` | ✅ 改服务端分页 |
| 卡池全量返回 | `/training/pool` | ✅ 服务端分页 |
| `pageSize=1000/999/10000` | 多个管理页 | ⏳ 见下 |

### 轮询层（setInterval 共 46 处）
- **乘风（通用）**：`8000ms` 释放状态轮询（PlayerTeam/SongSelection/SongGroup/CaptainChoice/Concurrent/Performance/PerformanceDraw）。
- **BB**：`1000~5000ms` 轮询（`BBHohView 2000`、`BBVetoCompetitionView 2000`、`BBMinigameLiveView 3000`、`BBEndgameView 2500`、`BBHouseAdminView 5000` 等）。
- **其它**：ChatView 10000ms。

### Socket 层（8 处）
仅 **BB / powerchallenge** 使用：`/bigbrother-game`、`/bigbrother-house`、`/bigbrother-minigame`、`/powerchallenge`。乘风速运赛已全部停用。

### 生命周期层
多数轮询有 `onBeforeUnmount` 清理；但**切到后台仍轮询**（未监听 `visibilitychange`）。

## 三、执行（已落地）
1. ✅ 停止乘风 WebSocket，页面改用轮询/手动刷新。
2. ✅ 布局层请求风暴修复：只刷新当前轮分组模式；tick 刷新按路径过滤 + 1s 去抖。
3. ✅ `useSfRefresh` 支持路径匹配 + 去抖，各页面仅在自己相关模块写入时刷新。
4. ✅ 服务端分页：歌曲库、操作日志、训练卡池。
5. ✅ 训练页属性面板「全部数据就绪后再展示」，避免占位数值。

## 四、待办（建议按序执行）
- [ ] **轮询可见性优化**：页面隐藏时暂停轮询（`document.visibilitychange`），回来再刷一次。
- [ ] **BB 轮询降频**：2000/2500ms → 4000~5000ms；并同样做可见性暂停。
- [ ] **管理页大表分页**：选手管理、训练记录、训练情况、排名总览、淘汰记录、日志统计。
- [ ] **`playerStore.fetchUsers({ pageSize: 1000 })`**：改为按需/缓存，避免每个页面挂载都拉全量用户。
- [ ] **路由懒加载/分包**：确认 `router` 已用 `() => import()`（已使用），并对大依赖（图表等）按需引入。
- [ ] **BB socket 抖动**：隧道下建议直连服务器地址，或对 socket 设置 `reconnectionDelayMax`、`randomizationFactor`。

---

## 五、验证方法
- 浏览器 DevTools → Network：观察请求数、是否有同一 URL 高频重复、是否有超大 `pageSize`。
- Performance / Reactivity：观察是否有长时间任务、密集重渲染。
- 后端日志：观察某接口 QPS。
